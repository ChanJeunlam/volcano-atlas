# 02 数据与照片

## 数据源分工

| 来源 | 用途 | 取数入口 | 限制 |
|---|---|---|---|
| Smithsonian Global Volcanism Program | 全球全新世火山目录、稳定编号、喷发资料 | https://volcano.si.edu/volcanolist_holocene.cfm | 按版本记录收录口径；不是全球实时传感器 |
| GVP Webservices / API | 自动导入的候选官方接口 | 从 GVP 官方导航进入并确认接口 | 本规划尚未实测接口，实施先验证协议/限制 |
| GVP 喷发查询 | 二期喷发历史 | https://volcano.si.edu/search_eruption.cfm | 保留确认程度和日期不确定性 |
| GVP / USGS Weekly Report | 二期近期报道 | https://volcano.si.edu/reports_weekly.cfm | 周报为报道记录，可能修订，不是无报道即无活动 |
| USGS VHP | 美国监测信息和官方资料 | https://www.usgs.gov/programs/VHP | 美国信息不能当作全球统一预警 |
| Wikimedia Commons | 具备文件级许可的火山图片 | MediaWiki Action API imageinfo/extmetadata | 每张单独核对作者、许可和地点 |

不要固定网站当前火山总数；显示导入成功的快照数量和范围。GVP 表格下载入口存在，具体 URL/格式在导入任务中读取官方页面验证。

## 首次导入步骤

1. 打开 GVP 全新世列表，确认版本、下载入口、引用和使用条款；选择官方 API（先探测）或下载表格，不先写页面抓取器。
2. 原始文件保存到 `data/raw/gvp/<date>/`；记录 URL、UTC 抓取时间、源版本、SHA-256、文件大小和内容类型。
3. 判断实际文件：SpreadsheetML XML 用 XML 解析，XLSX 用相应读取器；若拿到 HTML 错误页则中止。
4. 主键使用 GVP Volcano Number 字符串。去重以编号为准，不以名称为准。
5. 检查经纬度合法范围、数值可解析、必填字段和主键唯一；海拔可能为负，不能删除海底火山。
6. 保留源国家原文及标准化国家关系；跨国火山可对应多国。地区归属不依据点落入地图边界自动覆盖源信息。
7. 最近喷发年份保留原文及可解析数字。公元前年份、未知和不确定日期分别处理，不强行转成 JavaScript Date。
8. 输出干净 JSON、拒绝记录 CSV、数量/缺失/重复统计和字段映射文档。
9. 写入 staging/新快照，校验成功后原子切换活动快照；失败保留原目录，不发布部分数据。
10. 导出同版本公开轻量静态目录，供前端降级使用。原始大文件是否入 Git 取决于大小及许可，记录留存位置。

## 照片建立流程

1. 选取首批 20 座展示火山，如富士山、埃特纳、维苏威、基拉韦厄和圣海伦斯；每个目标先确认 GVP ID。
2. 建立 GVP ID → Wikidata QID/Commons 文件页的映射，核对坐标、国家和名称，防止同名火山匹配错误。
3. 从已匹配实体/人工候选获取文件，再用 imageinfo/extmetadata 获取 thumbnail、原始文件页、作者和许可元数据。
4. 入库前人工确认图片确实为该火山；优先景观照片，避免把地图、标志或另一座山作为封面。
5. 仅发布许可明确允许相应用途且满足署名条件的照片。许可缺失或含糊时先不展示图片，仅保留资料页链接。
6. 不把 GVP 图库全部当成可自由复制的素材；按文件来源/条款核验。USGS 页面里的第三方图片也单独核验。
7. 元数据中的 HTML 先清洗，前端优先以纯文本展示；禁止把上游原始 HTML 直接 v-html 注入。
8. 图片以缩略图首屏、大图点击加载；本地缓存/Storage 再发布前确认许可，保留 attribution。

字段：`author_text`、`license_code`、`license_url`、`source_page_url`、`image_url`、`thumbnail_url`、`caption`、`retrieved_at`、`reviewed_at`、`verification_status`。
界面提供完整署名；无法取得作者信息时依据具体许可处理，不能填“互联网”。

## 更新规则

首期手动更新并记录日志；稳定后再引入受控计划任务。目录可月度检查；活动报告按其官方发布节奏检查。抓取频率与服务条款共同决定，不能承诺全球实时。
图片不会每次访客点击都搜索上游。ETL 使用超时、有限退避、低并发和可恢复游标；403/429 中止或按允许方式延后。
每次更新保存差异报告：新增、修改、删除候选、错误和图片变更。数量突降时停止切换，人工比较源文件，不能误删旧目录。
